# AGENTS.md

MERRY is one app: an agentic invoice auditor in one Snowflake database. SQL checks flag invoice lines, a Cortex
Agent (`AGENT.MERRY_AGENT`) reviews each flag against the contract clauses and site records, and the analyst works
through the results in a Streamlit app (`APP.MERRY`: Dashboard, Issues, Ask MERRY, Data). Every screen and the chat
read the same `APP.V_UI_*` views and change data only through MERRY's procedures.

- Start with `README.md`, then `SETUP.md`, then `merry_agent/docs/PRODUCT.md`, `ARCHITECTURE.md` and `DECISIONS.md`
  (DECISIONS.md overrides the other two).
- **All account-specific names live in `settings.py`** (database, role, warehouse, compute pool, models). Code and
  SQL use the placeholders `{{DB}}`, `{{ROLE}}`, `{{WAREHOUSE}}`, `{{COMPUTE_POOL}}`, `{{MODEL}}`,
  `{{CONTRACT_MODEL}}`. Never write a database, role, warehouse, account, user name or model into code or docs.
- Database objects are in `merry_agent/sql/`, the chat in `merry_agent/app/`, the app's other tabs in the root
  `streamlit_app.py` and `dashboard.py`. `merry_chat/` and `snowflake.yml` are generated by setup: never edit them.

## Rules
1. **Never lose data on redeploy.** Tables are `CREATE TABLE IF NOT EXISTS` only. Setup code never drops, replaces or
   truncates a table, schema, database or stage (`deploy.py` refuses such statements). Views, functions, procedures,
   the semantic view, the agent, the task and the Streamlit app may be replaced. Emptying data is only done by the
   admin tool `merry_agent/tools/reset.py`, with a confirm.
2. **Answer keys stay out.** No pipeline, check, agent, tool, prompt or app code may read an answer key or evaluation
   data, use error IDs, or special-case an invoice or contract number. The app role gets no grant on any EVAL or
   SCRATCH schema.
3. **No hard-coded business values.** Rates, term dates, standby percentage, travel allowance, excluded charges and
   the operator's name come from the CONTRACT schema, filled by contract extraction.
4. **The LLM never invents money.** Every peso amount comes from SQL; agent text only explains it.
5. **No emailing.** Approving saves a PDF and sets a status.
6. **Currency.** PHP, `NUMBER(14,2)`. Write "PHP" in PDFs and ₱ in the app.
7. **Sample data is read-only.** `merry_agent/data/` is a copy of the synthetic pack; don't edit or regenerate it.
8. **Clean slate.** Setup creates every table empty and seeds only reference data (rule labels, status words, plain
   phrases). Site records, contracts and documents come in through the app, like any upload.
9. **Browser-facing behaviour is verified in a browser** (links, downloads, previews, layout); a server-side check is
   not proof.

## Changing MERRY
Edit `merry_agent/sql/` or `merry_agent/app/` (or the root app files), set up a test database first
(`python3 merry_agent/setup.py --db MERRY_TEST`), check it with
`python3 merry_agent/tools/run.py --db MERRY_TEST merry_agent/tools/smoke_test.py` (and `try_sample.py` when the
audit is affected), then run setup for the real database. When a task ends, report a short table (check, expected,
actual, PASS/FAIL) and list every object and file changed.
